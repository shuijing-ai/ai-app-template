# 05 · 结构化输出：包装类与安全解包

> 目标：掌握「XxxSet 约定 + strict schema + 安全解包」三件套，
> 让模型输出从「祈祷它是 JSON」变成「结构即契约」。
> 代码：`app/schema/wrappers.py`、`app/utils/extractor.py`。

## 1. 问题：模型输出的「野 JSON」光谱

即使提示词里写了「输出 JSON」，真实拿到的是：

```text
① 完美 JSON           {"findings": [...]}
② 围栏包裹            ```json\n{"findings": [...]}\n```
③ 前后废话            好的，以下是提取结果：{...} 希望有帮助！
④ 键名自作主张        {"results": [...]}        ← 说好的 findings 呢
⑤ 裸列表              [{...}, {...}]
⑥ 截断的 JSON         {"findings": [{"quote": "...(此处省略
```

②③④⑤ 由解包函数治，⑥ 由 strict 模式 + max_tokens 治，①是理想情况。
**每一条都在生成项目的测试里有对应用例**（tests/test_extractor.py）。

## 2. 第一道防线：strict json_schema（事前约束）

```python
class FindingItem(BaseModel):
    quote: str
    issue: str
    category: Literal["logic", "evidence", "style", "compliance"]
    severity: int = Field(ge=1, le=5)

class FindingSet(BaseModel):
    findings: list[FindingItem]

response_format = strict_json_schema(FindingSet)
```

OpenAI 的 structured outputs 模式在**模型端**保证合法 JSON。
`strict_json_schema` 做的适配只有一件事：递归给每个对象节点补
`additionalProperties: false` 并要求全字段——strict 模式的硬性要求。

三个容易翻车的细节：

1. **不要给字段默认值**：strict 模式要求所有字段必填，
   pydantic 有默认值的字段不会进 `required` 列表。
   「可空」用 `str | None` 表达（字段仍必填，值可以是 null）。
2. **description 就是提示词**：`Field(description="原文引用，必须逐字摘抄")`
   会进 schema 并显著提升引用质量——schema 是给模型看的另一份 prompt。
3. **枚举用 Literal**：比自由字符串稳定，下游不需要再清洗。

## 3. 第二道防线：safe_extract_items（事后兜底）

```python
def safe_extract_items(payload, key_hints=("items", "findings", "decisions")) -> list[dict]:
    if isinstance(payload, BaseModel): return safe_extract_items(payload.model_dump(), ...)
    if isinstance(payload, str):       payload = _load_json_text(去围栏(payload))
    if isinstance(payload, list):      return [v for v in payload if isinstance(v, dict)]
    if isinstance(payload, dict):      return _from_dict(payload, key_hints)
    return []
```

设计原则：**永不抛异常，最差返回空列表**。空列表在上游有明确语义
（提取失败 → 条件边重试 → 再失败降级继续），异常只会炸掉整条工作流。

`_from_dict` 的兜底顺序值得注意：先查约定键（findings），再退化为
「第一个值恰好是 list[dict] 的键」——这就是谱系 ④「键名自作主张」的解药。

## 4. XxxSet 约定：为什么所有输出都是「Set」

每个结构化输出都定义成包含列表字段的包装类（FindingSet/ReviewSet/
ResearchSet/CritiqueSet）。收益链：

1. strict schema 从包装类自动生成——不用手写 JSON Schema；
2. `safe_extract_items` 用同一套 key_hints 解包所有模型输出；
3. 评测的 schema_validity 就是 `FindingSet.model_validate(...)` 一行；
4. 新增输出类型 = 新增一个 pydantic 类，全链路自动生效。

对比反模式：节点里手写 `json.loads(resp)["findings"]`——
谱系 ②⑤⑥ 每一种都能让它崩，而且崩点散落在 N 个节点里。

## 5. 走读：extract 节点里的双层防线

```python
request = LLMRequest(..., response_format=strict_json_schema(FindingSet), ...)
response = gateway.complete(request)                  # 第一层：事前约束
items = safe_extract_items(response.content)           # 第二层：事后兜底
findings = [i for i in items if REQUIRED_KEYS.issubset(i)]   # 第三层：字段完备性
```

第三层常被忽略：就算 JSON 合法、键也对，模型偶尔会漏字段
（尤其长列表的后几条）。`REQUIRED_KEYS.issubset` 把残缺条目静默剔除，
配合 `FindingItem.model_validate`（评测里）形成完整闭环。
