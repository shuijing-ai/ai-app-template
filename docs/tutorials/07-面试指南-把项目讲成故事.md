# 07 · 面试指南：把项目讲成故事

> 目标：把这个项目组织成 3 分钟简介 + 20 分钟深挖 + 任意层追问的
> 弹药库。每道追问都标注了答案所在代码，确保「讲的每一句都有出处」。

## 1. 三分钟版本（项目介绍模板）

> 我开源了一个 AI 应用脚手架 ai-app-template。起因是观察到 LLM 应用从 demo
> 到生产之间隔着一层没人替中小团队做的工程脏活：重试降级、成本控制、
> 结构化输出、质量回归。它是一条命令生成项目的 CLI，内置三个模板
> （审阅流/RAG/多智能体），生成的项目有三个特点：离线测试全绿——
> 不需要 API Key 就能验证工程正确性；所有 LLM 调用走统一网关——
> 重试、熔断、跨供应商降级、成本统计都在这一个入口；自带评测体系——
> mock 模式进 CI 验管道，真实模式做质量门禁。我自己用它 X 周内
> 搭起了 Y（你的真实用例），网关层在供应商限流时保住了可用性。

最后一句必须替换成你的真实经历——**脚手架本身是铺垫，用出来的故事才是杀招**。

## 2. 高频追问与答案索引

### Q1「重试和降级不是框架自带吗，你做这个的意义？」

框架给的是积木（SDK 抛什么异常、compose 怎么配），不给的是**决策**：
哪些错误可重试（`gateway.is_retryable`：429/超时/网络 vs 401/400）、
退避怎么设（指数 + 抖动 + 上限，`_sleep_backoff`）、链上放谁
（跨供应商才防区域故障，`tier_chains` 配置）。这些决策每家都不同，
所以只能在自己的网关层沉淀。

### Q2「熔断器为什么自己写而不用库？」

30 行实现了 closed/open/half-open 的完整状态机（`CircuitBreaker`），
需求只有「连续失败 N 次跳过、冷却后放一次探测」。引 sentinel 要
多一个依赖与一套配置体系，复杂度超过了问题本身。**如果面试官追问
滑动窗口/慢调用比例，答：流量规模到了再换，接口已经隔离好了。**

### Q3「LLM 输出不稳定你们怎么治的？」

三层防线（教程 05）：事前 strict json_schema（模型端保证合法 JSON）、
事后 safe_extract_items（围栏/废话/键名漂移/裸列表统一解包，永不抛异常）、
字段完备性过滤。解出来仍为空 → 图的条件边重试一次 → 再失败降级继续。
有专门测试证明全链路（`test_llm_total_outage_degrades_gracefully`）。

### Q4「质量怎么保障的？」（必考）

评测集只写期望不绑实现；四指标：关键词命中/schema 合法/数量/延迟；
双门槛：mock 验管道进 CI（免费、每次提交），live 验质量配 Key 跑；
退出码即门禁，报告是 Markdown 表格直接贴 PR。（教程 06）

### Q5「为什么测试能离线跑？线上不是要调模型吗？」

两层替身：FakeGateway（节点级，测编排）+ ScriptedClient（SDK 级，
按模型名脚本化异常与响应，测网关弹性）。依赖注入点就一个参数
（`build_graph(gateway=...)` / `client_factory=...`）。CI 不需要密钥
与预算，还能故意注入 429 演练故障路径——**在线反而测不了故障**。

### Q6「多智能体怎么防止循环失控烧钱？」（multi-agent 模板）

两道终止保险：critic 给 pass 立即短路；轮次预算超限强制收尾返回
已有最佳产出（`supervisor_node._finish_message`）。调度规则确定性优先：
第 1 轮必调研、pass 必收尾，LLM 只做真正需要判断的中间调度——
**可解释的编排边界**比全自动智能体更适合生产。

### Q7「RAG 怎么防止模型编造引用？」（rag-agent 模板）

生成节点强制 doc_id + 逐字引用；verify 节点是 30 行确定性校验
（doc_id 必须在检索结果中、quote 前 40 字忽略空白后必须逐字存在），
伪造引用被剔除并带着失败原因重试一次。`test_forged_citation_is_stripped_and_retried`
可现场演示。

### Q8「成本怎么控制的？」

成本感知路由：任务类型 + 输入长度 + 结构化要求 → light/standard/heavy
三档（规则透明可解释，`router.classify`）；注册表带价格，
`GatewayStats` 按模型统计到 1e-6 美元精度，/health 直接可查。

### Q9「这个项目最难/最坑的地方？」

真实故事候选（都在仓库历史里）：
- 入口点写错成回调函数，CLI 静默退出 0——包装层必须有端到端测试
  （`test_console_script_entry_point`）
- `round(cost, 6)` 把 4.5e-6 美元四舍五入成 5e-6——小数精度测试
- 字级 TF-IDF 让「上市」匹配到「城市」——分词粒度的取舍
- 多智能体有状态替身在评测用例间串场——测试隔离意识

## 3. 讲解演示脚本（5 分钟 live demo）

```
1. ai-app-template list                          （10s：三个模板）
2. ai-app-template create demo -t rag-agent --yes （20s：生成）
3. cd demo && pytest -q                        （30s：离线全绿，强调无 Key）
4. python -m app.eval.run_eval --mock          （20s：评测表格）
5. 打开 gateway.py 讲 40 秒三层弹性            （代码即幻灯片）
6. uvicorn 起服务 curl /health                  （40s：统计与熔断状态可见）
```

## 4. 反模式提醒

- ❌ 背数字：「支持 3 种模板 19 个测试」——没人记得住，讲机制不讲 KPI
- ❌ 贬低 LangChain 抬高自己——说「按需裁剪依赖」（ADR-3 的措辞）
- ❌ 声称没踩过的坑——本文档列的坑都有代码出处，被追问时能现场打开
- ❌ 只讲脚手架本身——一定要接「我用它做了 X」
